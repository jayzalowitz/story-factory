# A practice research folder

These files are **illustrative scaffolds, not completed research**. The invented example is a community radio station during a fictional storm. Every `example.invalid` address is deliberately nonfunctional. No source was consulted, no event verified, no person identified, and no permission obtained.

Copy the shape into your project's `development/` folder, replacing the examples with your own brief and inspected evidence:

- `source_mode.json` → `research/source_mode.json`
- `claims.json` → `research/claims.json`

Do not copy sample claims into a real story as facts. Keep a source only after you have inspected it, recorded a precise location, and checked what it actually supports. Sample source metadata is deliberately labeled as a placeholder; a URL's presence proves nothing.

Try these conversations with your installed story skill:

> Start an original story about a radio operator who must choose which caller to believe during a storm. Research how a small station operates, but keep all people and events invented.

> Run story-research for a based-on project using the records I supplied. Use native subagents for chronology, relationships, and context if this host supports them. Show contrary evidence and keep my private records local.

> Run story-truth on our inspired-by outline. Show which scenes borrow documented events, which infer motives, and which are invented. Check that the pitch describes that distinction honestly.

In Claude these correspond to `/story-research` and `/story-truth` after command installation. In Codex, ask the installed `story` skill for the same workflow by name. See `skills/story/references/RESEARCH.md` for the complete process, budgets, sequential fallback, and review criteria.

The `unverified`, `inference`, and `invented` entries demonstrate different states. This fixture intentionally has no `verified` claim because no real research occurred. A production ledger may also use `disputed` and should retain the actual competing evidence.
