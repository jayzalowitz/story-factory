# Keep a long film coherent across finite sessions

The assistant's current context is limited. A full screenplay, sources, alternate drafts, reviews, package and repeated conversation can exceed it. Larger windows and provider compaction help; they do not create unlimited attention, exact recall or output length. Do not promise that one command means one response, one context window, or uninterrupted execution.

## Start with durable project state

Read development/status.md, the brief, story bible, scene map, current workflow status, recent revision log and unresolved decisions first. Identify the actual current sources and fingerprints. Use existing writer approvals; do not repeat answered interviews. Locate the next action before loading large files. If these records conflict with each other or the manuscript, inspect the source and resolve the conflict explicitly.

The manuscript, source ledger and writer-approved decision records govern. A chat recap or optional memory recall is a pointer, not authority to change them. Recalled notes must identify their story, provenance and applicable version; verify against the actual project before applying. Never silently import a fixture, another production's canon, or an obsolete decision.

## Read and write in purposeful scopes

- Load only references and files needed for the stage. Do not dump every historical example, old draft, PDF, model transcript and research page into every request.
- Draft in coherent scene/sequence groups. Read the relevant setup, adjacent scenes, continuity and ending consequences; save complete writing to source files. Keep scene IDs stable and update the story bible/scene map after substantive changes.
- A full-draft review must actually read the complete current draft. If it does not fit one context, divide the source into contiguous scopes, record each file/hash and covered scene IDs in development/reading_log.md, then reconcile cross-sequence setups/payoffs, chronology, arcs and ending against the same version. Summaries alone do not count as reading unseen scenes. Never claim a fresh full read from excerpts.
- After revisions, distinguish retained original coverage, targeted rereads and any necessary fresh complete read. Source changes invalidate relevant earlier coverage and quality/truth/build receipts. Run the actual current checks before delivery.
- Optional helpers receive narrow, disjoint assignments and return findings/source pointers, not competing screenplay versions. One coordinator resolves conflicts into the canonical files. Helpers also have context and usage limits; more agents do not create unlimited reliable memory.

## Checkpoint before you lose the thread

At meaningful stage/sequence boundaries, before a long build or tool run, and before ending/compacting a session, update development/status.md and development/checkpoint.md. Include current stage and source fingerprint, completed and unread scopes, approved decisions/constraints, unresolved finding IDs, concrete next file/scene/action, and current tool/blocker state. Distinguish drafted, reviewed, revised, built and inspected. Save actual work before summarizing it.

Do not invent remaining token capacity, provider allowance or a successful compaction. If a host exposes a budget, use it to leave space for writing and the checkpoint. Otherwise keep outputs and tool reads bounded and checkpoint proactively. On an interruption, reconstruct from current files and receipts; do not restart or overwrite work simply because the chat history is short.

Use /story-resume in Claude Code or $story-resume in Codex. Run workflow status, verify current hashes and reopen stale stages. Explain one concise recap and continue the next agreed step. A missing tool or unresolved creative blocker remains visible. No infinite retries or repeated whole-project model reviews: follow DELIVERY.md's bounded repair plan and report remaining issues honestly.

When reporting progress, compare your recap to the actual workflow output: exact next stage, stale stages and blockers. A manuscript's existence does not prove every prerequisite was reviewed. Resolve files-ahead-of-receipts explicitly without erasing the manuscript or silently marking stages complete. Quote recalled fixture/decision content accurately and distinguish it from current manuscript canon.
